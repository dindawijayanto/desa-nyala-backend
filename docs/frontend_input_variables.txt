DESANYALA - DAFTAR NAMA VARIABEL INPUT FRONTEND
Versi desain: desanyala_input_cards.html
Tujuan: membantu integrasi frontend dengan backend DesaNyala dan adapter Offgridders.

PENTING
1. Nama ID HTML di bawah adalah nama aktual yang digunakan di file HTML saat ini.
2. Nama properti JSON adalah kontrak input yang dibentuk oleh fungsi buildConfig() di HTML.
3. Kontrak JSON ini adalah format DesaNyala yang diusulkan, BUKAN format input native Offgridders. Backend/adapter perlu menerjemahkannya ke workbook dan time series yang dibutuhkan Offgridders.
4. Profil beban per jam dan profil PV per jam BELUM dibuat oleh HTML saat ini. Di JSON, hal ini ditandai dengan profile_generation_method='not_implemented' dan hourly_profile_source='not_configured'. Jangan menganggap konfigurasi tersebut bisa langsung menjalankan optimizer tanpa backend tambahan.
5. Format angka: frontend menyimpan nilai numerik sebagai number; persentase pada JSON umumnya dikonversi menjadi pecahan 0..1.

B. CARD 02 - ELECTRICITY DEMAND
============================================================
Daftar peralatan bersifat dinamis. Setiap baris menggunakan atribut data-key:

HTML data-key        JSON path dalam setiap item demand.loads[]      Tipe / satuan
category             demand.loads[].category                         string
                     Kategori yang tersedia: Rumah tangga, Sekolah,
                     Puskesmas, Pompa air, UMKM, Fasilitas umum, Lainnya
device               demand.loads[].device                           string
quantity             demand.loads[].quantity                         integer, unit
power_w              demand.loads[].power_w                          number, watt per unit
hours_per_day        demand.loads[].hours_per_day                     number, jam/hari
(hasil hitung)       demand.loads[].estimated_kwh_day                number, kWh/hari

Ringkasan yang tampil di UI (bukan input pengguna):
HTML ID             Arti
 dailyEnergy        Total estimasi energi semua peralatan, kWh/hari
 annualEnergy       Estimasi energi tahunan = energi harian x 365, kWh/tahun
 connectedPower     Jumlah daya terpasang peralatan, kW
 equipmentCount     Jumlah baris peralatan
 sideDaily          Salinan ringkasan energi harian di sidebar

Properti demand JSON lain:
demand.profile_source                 string, saat ini 'equipment_estimate'
demand.estimated_daily_energy_kwh     number, kWh/hari
demand.estimated_annual_energy_kwh    number, kWh/tahun
demand.profile_generation_method      string, saat ini 'not_implemented'

CATATAN: estimated_kwh_day dihitung dari quantity * power_w * hours_per_day / 1000.
Formula ini hanya estimasi energi; belum membentuk profil beban per jam, faktor keserentakan,
perbedaan pola antarhari, atau beban puncak aktual. Backend harus membuat profil per jam.

D. CARD 04 - DIESEL GENERATOR
============================================================
HTML ID       JSON path                              Tipe / satuan
 genMode      generators.mode                        enum: existing | new
genCount     generators.unit_count                   integer, unit genset
genPower     generators.rated_power_each_kw           number, kW per unit
 genMinLoad   generators.min_loading_fraction         number, pecahan 0..1
genMaxLoad   generators.max_loading_fraction         number, pecahan 0..1
fuelPrice     generators.fuel_price_per_liter         number, biaya/liter
fuelCurve     generators.fuel_model                   enum: default | efficiency | curve
genEfficiency generators.efficiency_fraction          number, pecahan 0..1
genCapex      generators.capex_per_kw                number, biaya/kW
genOpex       generators.opex_annual_per_unit         number, biaya/unit/tahun
genLife       generators.lifetime_years               integer, tahun

Properti generator konstan dalam JSON:
generators.identical_units_assumption                boolean, saat ini true
generators.unit_commitment_model                     string, saat ini 'requires_validation'

CATATAN KRITIS:
- Form menganggap unit genset identik: unit_count x rated_power_each_kw.
- Ini belum membuktikan engine Offgridders mengoptimalkan hidup/mati setiap genset satu per satu.
- Bila fitur unit commitment dikembangkan, kemungkinan perlu generators[] per unit dengan generator_id,
  rated_power_kw, min/max loading, startup cost, minimum up/down time, dan fuel curve per unit.
- Pastikan model bahan bakar di backend cocok dengan fuel_model. 'curve' saat ini hanya pilihan UI,
  bukan file kurva yang sudah dikirim.

F. CARD 06 - ECONOMIC ASSUMPTIONS
============================================================
HTML ID        JSON path                              Tipe / satuan
currency       project.currency                       enum: IDR | USD

pada eksperimen sebelumnya menghasilkan warning; jangan gunakan nilai nonzero tanpa validasi.

G. CARD 07 - RELIABILITY & OPTIMIZATION
============================================================
HTML ID           JSON path                                   Tipe / satuan
targetReliability reliability.target_supply_fraction         number, pecahan 0..1
shortagePolicy    reliability.shortage_policy                enum: forbid | bounded
maxUnmet          reliability.max_unmet_energy_fraction      number, pecahan 0..1; hanya dipakai jika policy=bounded
reserveMargin     reliability.reserve_margin_fraction       number, pecahan 0..1
objective         optimization.objective                     enum: annualized_cost | fuel_consumption
scenarioDiesel    hasil optimization.scenarios[].id          checkbox skenario diesel-only
scenarioPv        hasil optimization.scenarios[].id          checkbox skenario PV + diesel
scenarioBattery   hasil optimization.scenarios[].id          checkbox skenario PV + diesel + baterai

Format item optimization.scenarios[]:
- {"id":"diesel_only", "pv":false, "battery":false}
- {"id":"pv_diesel", "pv":true, "battery":false}
- {"id":"pv_diesel_battery", "pv":true, "battery":true}
  Catatan: properti battery pada skenario ketiga mengikuti batteryEnabled.

Properti optimizer lain:
optimization.solver_configuration = 'backend_default'

CATATAN:
- objective='fuel_consumption' tersedia sebagai opsi UI, tetapi backend harus menyediakan fungsi objektif yang
  benar-benar meminimalkan konsumsi bahan bakar. Jangan hanya mengubah label/field jika model tidak mendukungnya.
- target_supply_fraction dan reserve_margin_fraction merupakan kontrak DesaNyala; perlu diterjemahkan menjadi
  kendala matematika yang sesuai. Tidak semuanya merupakan field native langsung pada Offgridders.

targetReliability, shortagePolicy, maxUnmet, objective, reserveMargin, scenarioDiesel,
scenarioPv, scenarioBattery.

Input peralatan (elemen dinamis):
- Kontainer: #equipmentList
- Tiap baris: [data-load-row]
- Field dalam baris: [data-key="category"], [data-key="device"],
  [data-key="quantity"], [data-key="power_w"], [data-key="hours_per_day"]
- Tombol tambah: #addEquipmentBtn

Elemen UI non-payload / elemen status:
configForm, errorBox, card-project, card-demand, card-pv, card-gen, card-battery,
card-economics, card-optimization, addEquipmentBtn, dailyEnergy, annualEnergy,
connectedPower, pvFields, pvFixedWrap, genEfficiencyWrap, batteryFields, unmetWrap,
resetBtn, previewBtn, readinessBar, readinessText, readinessPercent, equipmentCount,
sideDaily, sideGen, sidePv, sideBattery, scenarioSummary, jsonModal, jsonTitle,
closeModalBtn, jsonOutput, downloadJsonBtn, copyJsonBtn, saveDraftBtn, toast.

Fungsi JS penting saat ini (scope lokal di IIFE, belum diekspos global):
- getLoads()       : membaca semua baris alat dan menghitung estimasi kWh/hari.
- getScenarios()   : membentuk array skenario yang dipilih.
- buildConfig()    : membangun payload JSON lengkap.
- validate()       : validasi input dasar.
- updateSummary()  : memperbarui ringkasan sidebar dan kesiapan form.

Jika backend ingin memakai buildConfig() secara langsung, ubah supaya diekspor melalui handler submit/API
atau pindahkan fungsi serializer ke modul JavaScript yang bisa diimpor. Saat ini tombol pratinjau hanya
menampilkan JSON, dan tombol unduh menyimpan JSON lokal; belum ada fetch() ke backend.

============================================================
K. SARAN KONTRAK API
============================================================
Endpoint usulan:
POST /api/v1/optimizations
Request body: objek JSON dari buildConfig()
Response perlu minimal memuat:
- status: optimal | feasible | infeasible | error
- scenario_results[]: metrik tiap skenario
- capacities: kapasitas PV, genset, baterai
- annual_cost, lcoe, annual_fuel_liters, renewable_share, supply_reliability, unmet_energy_kwh
- dispatch[]: timestamp, demand_kw, pv_kw, generator_power_kw, battery_charge_kw, battery_discharge_kw, battery_soc_kwh
- validation: energy_balance_passed, reliability_passed, solver_message

Jangan menampilkan respons sebagai 'hasil optimal' bila solver gagal atau validasi kendala gagal.
