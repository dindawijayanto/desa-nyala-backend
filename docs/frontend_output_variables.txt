DESANYALA — DAFTAR NAMA VARIABEL OUTPUT FRONTEND
Versi desain: desanyala_output_dashboard.html
Tujuan: kontrak output yang diusulkan untuk menyambungkan backend optimasi DesaNyala ke halaman hasil.

PENTING
1. Nama JSON di dokumen ini adalah kontrak API DesaNyala yang diusulkan, bukan nama kolom native Offgridders.
2. Dashboard HTML ini menggunakan metrik hasil baseline Offgridders 365 hari yang diberikan pengguna. HTML tidak menjalankan optimasi.
3. Hasil diesel-only belum tersedia di baseline yang disediakan dan karenanya harus diberi status pending, bukan diisi angka rekaan.
4. LCOE baseline memakai satuan generik currency/kWh. Jangan tampilkan sebagai IDR/kWh sebelum satuan dan konfigurasi biaya diverifikasi.
5. Dispatch per jam yang tersedia adalah keluaran baseline 8760 interval dari dua skenario PV+diesel dan PV+diesel+baterai. Tampilan detail HTML merender 96 interval pertama untuk demo; ekspor ringkasan harian memakai 365 baris hasil agregasi.

  "generated_at": "ISO-8601 timestamp",
  "period_days": 365,
  "time_step_hours": 1,
  "units": {
    "currency": "IDR",
    "energy": "kWh",
    "power": "kW",
    "pv_capacity": "kWp",
    "fuel": "liter",
    "emissions": "kgCO2eq"
  },
  "selected_scenario_id": "pv-diesel-storage-mg",
  "scenario_results": [],
  "validation": {},
  "warnings": []
}

Catatan: units.currency harus berasal dari konfigurasi proyek yang tervalidasi. Jangan mengasumsikan IDR bila input model menggunakan mata uang generik.

D. VARIABLE DISPATCH PER INTERVAL
============================================================
dispatch[] item:
  timestamp                 string ISO-8601
  demand_kw                 number, kW
  pv_kw                     number, kW
  generator_power_kw        number, kW (aggregate; untuk multi-unit gunakan generators[])
  battery_charge_kw         number, kW
  battery_discharge_kw      number, kW
  battery_soc_kwh           number, kWh energi tersimpan
  battery_soc_fraction      number, 0..1 (opsional untuk UI persentase)
  excess_power_kw           number, kW atau energy_kwh per interval; pilih satu definisi konsisten
  unmet_demand_kw           number, kW atau energy_kwh per interval; pilih satu definisi konsisten

Jika optimasi multi-genset sudah dikembangkan, tambahkan:
  generators[]: { generator_id, is_on, power_output_kw, fuel_liters_per_hour }
Jangan isi generator_id / status hidup-mati per unit jika engine masih hanya menghasilkan kapasitas genset agregat.

============================================================
G. VALIDASI DAN IMPLEMENTASI
============================================================
- HTML output saat ini tidak menjalankan optimizer. Data hasil hanya dari baseline yang dikirim dalam percakapan.
- Endpoint yang disarankan: POST /api/v1/optimizations dan GET /api/v1/optimizations/{run_id}.
- Status solver harus dipisahkan dari status validasi. Jangan sebut hasil "optimal" bila solver atau cek kendala gagal.
- Tentukan konsisten apakah dispatch menyimpan daya rata-rata kW atau energi per interval kWh. Interval di contoh 1 jam, sehingga jumlah kW per baris numerik kebetulan sama dengan kWh per interval tetapi satuannya tetap berbeda.
- LCOE dalam hasil sumber tertulis currency/kWh; konfirmasi unit biaya sebelum mengubah label ke IDR/kWh.
- Reliability perlu didefinisikan dari energi terpenuhi / kebutuhan, bukan dari nama field saja.
